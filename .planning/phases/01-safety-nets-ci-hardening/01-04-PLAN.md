<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Measured baseline → committed config | An erroneous baseline number silently allows coverage to drop |
| Executor → CI step ordering | Misplacing the new step (e.g. AFTER Build) defeats fail-fast |
| Test authorship (Task 3) → CI pass | Vacuous tests (import-only) inflate coverage without real assertions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `--cov-fail-under=<N>` value in pytest.ini | mitigate | Task 1 checkpoint requires 3 measurement runs; D-02 forces FLOOR of observed values. PR description captures the three raw numbers so reviewers can verify the committed floor is correct. Any future PR that tries to lower `--cov-fail-under` will be a visible single-line diff in the pytest.ini review. |
| T-04-02 | Spoofing | Task 3 vacuous tests (import-only) | mitigate | Acceptance criterion: every new test file contains at least one `expect(...)` assertion. Human-verify review at PR time is the second line of defense — reviewers can grep each new test for real behavior-assertion patterns. |
| T-04-03 | Denial of Service | Vitest threshold regression | accept | If a future upstream vitest minor release changes threshold-violation exit behavior, this plan's gate becomes advisory. Mitigation: RESEARCH.md Pitfall 5 documents the migration path; Dependabot (Plan 08) raises visibility of future vitest minor bumps. |
| T-04-04 | Tampering | CI step reordering (moving `Run tests` after `Build application`) | mitigate | Acceptance criterion explicitly asserts `i_audit < i_run < i_build` order via yaml parser. Any reorder fails Task 4's verify command. |
| T-04-05 | Information Disclosure | Baseline number in PR description | accept | Coverage percentage is not sensitive. Reveals test breadth but not a secret. |

Severity summary: all threats low/medium. The highest-value mitigations are (a) the three-run baseline measurement at Task 1 and (b) the yaml-parser-based step-order check at Task 4.
