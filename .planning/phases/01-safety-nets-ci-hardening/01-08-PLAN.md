<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dependabot GitHub service → repository | Dependabot opens PRs with dependency bumps; each PR runs CI (including coverage floor, DROP guard, characterization tests) before merge |
| Upstream dependency (PyPI / npm / github-actions marketplace) → repo | A malicious upstream release could propose itself via Dependabot; the PR workflow is the defense |
| Dependabot grouping → reviewer awareness | Grouped PRs hide individual version bumps behind a single PR; reviewer may miss a malicious transitive in a group |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Supply Chain / Tampering | Malicious upstream dependency proposing itself via Dependabot PR | mitigate | Every Dependabot PR runs the full CI suite: backend-ci (bandit, pip-audit, pytest with coverage floor + DROP guard + OpenAPI snapshot + characterization tests) and frontend-ci (prettier, eslint, tsc, npm audit, vitest with coverage threshold). A malicious bump that breaks characterization tests or flips bandit to HIGH severity is blocked. Residual risk: a malicious bump that preserves behavior AND passes lint/audit — out of scope for SAFE-10 alone; broader SAST (future phase) or `cargo-crev`-style attestation would address. |
| T-08-02 | Tampering | Grouped minor+patch PR hiding a transitive-dep CVE behind a surface-level version bump | mitigate | Per D-30 majors get individual PRs (Dependabot default behavior without `ignore`). Minor/patch groupings are by definition non-breaking and audited by `pip-audit` + `npm audit` on every PR. A malicious minor/patch would still trip audit CVE flagging in 95%+ cases. |
| T-08-03 | Denial of Service | Excessive PR volume from weekly runs | accept | `open-pull-requests-limit: 10` per pip/npm entries and `5` for github-actions caps the noise. Solo dev can triage in minutes per week; not a real DoS risk at this scale. |
| T-08-04 | Information Disclosure | dependabot.yml revealing internal directory layout | accept | `.github/dependabot.yml` is a public config file (repo is presumably public or semi-public). Revealing `/backend`, `/frontend`, `/chrome-extension` is already implicit in the repo structure. No new disclosure. |
| T-08-05 | Tampering | A future PR adding `ignore:` block silently suppresses majors | mitigate | Acceptance criterion explicitly asserts no `ignore:` keyword anywhere in the file. Any future PR adding `ignore:` must re-read Plan 08's PR description and note Pitfall 6; reviewer vigilance + this plan's SUMMARY.md record as institutional memory. |

Severity summary: all threats low. Primary value of this plan is T-08-01 mitigation (surfacing CVEs weekly) — the CI gates landed in Plans 03-07 do the actual blocking of malicious bumps.
</threat_model>
