# S01: Schema contract + crawler test infrastructure

**Goal:** Lay the schema contract that every subsequent M002 slice consumes: a central SpecRegistry with three concrete CategorySpec subclasses, a `category_targets` extension point on the adapter base, a `specifications` field on ScrapedPayload, an ingest validation hook that drops invalid spec blocks (without regressing existing part ingest), and crawler test infrastructure (conftest + tracked HTML fixture loader) plus contract tests proving the wiring.
**Demo:** Run pytest backend/app/crawlers/ — universal-extractor fixture stubs and 3 category-schema contract tests pass. SpecRegistry.resolve('coilover') returns the CoiloverSpec model. Ingest accepts a valid spec block, ingests it; ingest rejects a malformed spec block, ingests the part with specifications=null, and increments extraction_failure_rate.

## Must-Haves

- After this: Run `pytest backend/tests/crawlers/ -n auto` — universal-extractor fixture stubs and 3 category-schema contract tests pass. `SpecRegistry.resolve('coilover')` returns the `CoiloverSpec` model. Ingest accepts a valid spec block and persists it on `Part.specifications`; ingest rejects a malformed spec block, ingests the part with `specifications=None`, logs a structured warning, and emits an `extraction_failure_rate` CloudWatch EMF metric for the offending adapter.

## Proof Level

- This slice proves: contract — this slice proves the schema/registry/validation contracts that S02-S04 will consume. Real runtime required: yes (ingest hook exercised end-to-end with sqlite test DB). Human/UAT required: no.

## Integration Closure

Upstream surfaces consumed: `app.crawlers.adapters.base.RetailerCrawlerAdapter` (extended with `category_targets` ClassVar), `app.crawlers.base.ScrapedPayload` (extended with `specifications` field), `app.crawlers.base.ingest_payload` (extended with validation hook), `app.api.schemas.part.PartCreate` (already accepts specifications, no change). New wiring introduced in this slice: SpecRegistry module, three concrete spec models, conftest with HTML-fixture loader. What remains before the milestone is truly usable end-to-end: S02 universal-field extractors must auto-run via base-class post-hook; S03 must propagate `category_targets` to all 111 adapters; S04 must surface admin extraction-health.

## Verification

- Runtime signals: structured WARN log on Pydantic validation failure with adapter_name + product_url + ValidationError summary; CloudWatch EMF metric `extraction_failure_rate` with dimension `AdapterName × Environment` emitted from inside `ingest_payload` whenever a spec block is rejected. Inspection surfaces: CloudWatch Logs Insights filter on the warning shape; `Part.specifications IS NULL` queryable in DB; per-adapter rejection count rolled up in S04's admin extraction-health endpoint. Failure visibility: rejection cause (Pydantic error path), category slug attempted, and adapter name all land in the warning. Redaction constraints: none — adapter names and category slugs are not user-controlled.

- [x] **T01: Build SpecRegistry, CategorySpec base, and three concrete category models** `est:1h30m`
  Create the schema contract foundation that every downstream slice consumes. Add a new `app/crawlers/specs/` package with three modules: `base.py` (the abstract `CategorySpec(BaseModel)` with confidence-flag conventions and shared field metadata), `registry.py` (the `SpecRegistry` class with `register()` and `resolve(category_id: str) -> Type[CategorySpec] | None` plus a module-level singleton that auto-registers known specs), and three concrete models in `coilover.py`, `brake.py`, `turbo.py`. CategorySpec uses Pydantic v2 (the project's standard — see `app/api/schemas/`), `ConfigDict(extra='forbid')` so unknown fields fail loudly, and an Optional[str] `confidence` field on every value field via a small helper `SpecField` Annotated alias (e.g., `weight: SpecField[Optional[float]] = None` with companion `weight_confidence: Optional[Literal['high','medium','low']] = None`). Initial fields per the roadmap: CoiloverSpec → spring_rate_front (lb/in), spring_rate_rear, damper_adjustability ('non-adjustable'|'rebound-only'|'rebound-and-compression'|'electronic'), height_adjustable (bool); BrakeSpec → rotor_diameter_mm, pad_compound (str free-form for now), piston_count, vented (bool); TurboSpec → compressor_wheel_mm, turbine_wheel_mm, journal_or_bb ('journal'|'ballbearing'), housing_ar (float). Keep field counts modest — 3-5 each — these are stub schemas to prove the registry contract; the M002 retrofit slices expand them. Registry keys are category slug strings ('coilover', 'brake', 'turbo'), NOT category UUIDs (slugs are stable across environments; UUIDs are not). The registry must be a class with method-level access (not a module global dict) so tests can construct an isolated instance. Provide a default `default_registry` instance with the three specs pre-registered. No runtime hook from adapters or ingest in this task — purely the contract.

Wire `validated_specifications` into the `PartCreate(...)` constructor (specifications=validated_specifications). Update `runner.py` and `ecs_runner.py` and `ecs_rescrape_runner.py` to pass `adapter_name=adapter.ADAPTER_NAME` to `ingest_payload` (search for existing `ingest_payload(` call sites — there should be a small handful).
