# S10: Parts catalog redesign

**Reskinned /parts (PartsCatalog + filter sidebar + active-filter chips + PartList row actions + AddToBuildListDialog) onto S08 design-system primitives, preserved S06 sparkline+delta integration and R020 keyboard accessibility, and landed Playwright e2e parts-catalog.spec.ts at mobile/tablet/desktop with focus/Escape and Tab assertions.**

## What Happened

S10 migrates the /parts catalog page from the legacy hand-rolled `components/common/` and `components/buttons/` primitives onto the S08 design system (`components/ui/*`) without touching layout chrome (PageHeader, Pagination, Card, SectionHeader, ErrorAlert, LoadingSpinner, VehicleFilterSection) — those are explicitly reserved for the S12 ripple sweep per MEM107.

**T01 — page-level chrome + filters.** Three files touched. `PartsCatalog.tsx` swapped `common/Input` for `ui/Input` on the search field and added `data-testid='parts-catalog-search'` for the T04 keyboard test. `PartsFilterSidebar.tsx` migrated the price-min/price-max number inputs and the part-manufacturer search input onto `ui/Input`, retired `checkboxInputClass` (legacy bg-gray-800/border-gray-500/indigo palette) for token-driven `accent-primary border-input bg-background focus-visible:ring-2 focus-visible:ring-ring`, and converted the three clear-buttons onto `ui/Button` (variant='link' size='sm' h-auto p-0 for the top-right 'Clear all' inline link, and variant='ghost' size='sm' block w-full text-left justify-start h-auto for the per-section clears to preserve the legacy block-left layout against the ghost variant's default centered/h-9 sizing). `PartsActiveFilterChips.tsx` converted the four per-chip remove buttons (category/manufacturer/vehicle/price) onto `ui/Button variant='ghost' size='icon' className='h-5 w-5 p-0 rounded-full'` so they fit compactly inside the chip span (icon variant defaults to h-10 w-10).

**T02 — row action buttons.** `PartList.tsx` migrated all six row-action button usages (3 actions × 2 layouts) onto `ui/Button`: Add to Build List uses the default variant (hero action) and the table-layout instance got `data-testid='parts-catalog-add-to-build-list-trigger'` for T04's dialog test (card layout testid omitted — it's only used outside the catalog). Edit moved to `variant='secondary'` and Delete to `variant='destructive'` per MEM111 ('switch to formal variants where the design tokens already encode the intended semantic'); the bespoke `bg-red-600 hover:bg-red-700` override was dropped on Delete since `buttonVariants` already encodes it via `bg-destructive` / `hover:bg-destructive/90`. The text-xs px-2 py-1 / text-xs px-3 py-1 size overrides and the leading 📋 emoji on the card-layout Add-to-Build-List affordance were preserved verbatim. SortableTh, ResponsiveTableWrapper, the column-priority logic, the cache logic, the sort logic, the `providedData`/`providedPagination` prop contract, and the SparklineCell + PriceDeltaLine integration (S06) all stay unchanged — the S06 invariant (one batch POST per page + per-row lazy multi-observation fetches) remains intact.

**T03 — AddToBuildListDialog.** `AddToBuildListDialog.tsx` swapped `common/Dialog` for `ui/Dialog` (+ DialogContent/DialogHeader/DialogTitle) using Radix's open/onOpenChange API, sized DialogContent to `sm:max-w-3xl max-h-[90vh] overflow-y-auto` (slight narrowing from the legacy 4xl-equivalent — documented as intentional), tagged it with `data-testid='parts-catalog-add-to-build-list-dialog'` for the T04 dialog test. Footer buttons migrated to `ui/Button`: Cancel uses `variant='secondary' disabled={isAdding}`; Submit uses `loading={isAdding}` (Loader2 spinner via lucide auto-replaces the legacy LoadingSpinner ternary) + `disabled={selectedBuildListIds.size === 0}` for the empty-selection guard + `data-testid='parts-catalog-add-to-build-list-submit'`. The form contract (handleSubmit awaits buildListPartsApi.addPartToBuildList per selected list with Math.max(1, quantity) clamp, error/loading state, onPartAdded() + onClose() on success) is preserved exactly. Inner Cards (part preview, build-list rows), the raw quantity number input, the car-mismatch banner, ErrorAlert, and the build-list-fetch LoadingSpinner stay on legacy primitives for the S12 sweep.

**T04 — Playwright e2e.** Authored `frontend/e2e/parts-catalog.spec.ts` modeled on price-history.spec.ts (S06) and build-list.spec.ts (S09). The spec mocks the full /api/* surface needed by /parts (auth → MOCK_USER 200, app-settings, categories, part-manufacturers, car-generations stats/by-ids, parts/with-votes returning a 3-part fixture mirroring the multi/single/zero-observation pattern from S06, parts/filter-options, /parts/{id}/price-history GET for SparklineCell lazy fetches, POST /parts/price-history batch with route counter, /build-lists/user/{userId} for the multi-select). Three tests: (1) parts catalog visual regression at mobile/tablet/desktop — scrolls the multi-observation row into view (MEM079/MEM083), asserts sparkline [role='img'] visible, asserts exactly 1 batch POST (S06 invariant) via both route counter and request listener, then `toHaveScreenshot fullPage`; (2) AddToBuildList dialog focus/Escape (desktop-only via testInfo.project.name per MEM105) — uses `page.setViewportSize({ width: 2400, height: 900 })` BEFORE setupPage to keep the responsive table's `actions` column in the DOM (priority-7 column drops at the default 1280 desktop viewport — captured as MEM114), clicks the trigger, asserts dialog visible, asserts `document.activeElement` is contained by the dialog (Radix focus trap), presses Escape, asserts dialog hidden; (3) Tab traversal (desktop-only) — tabs up to 30 times until `document.activeElement.dataset.testid === 'parts-catalog-search'`, asserts the focused element matches `:focus-visible` AND has non-empty outline OR boxShadow (R020 visible focus ring on ui/Input). Conventions: page.route regex `/\/api\/(?!.*\.ts)/` (MEM082), pre-accepted cookie consent (MEM098), pre-dismissed chrome-extension promo (MEM108), pinned Date.now to FIXED_NOW_ISO, page.on('pageerror') re-throws, default 404 mock-miss for drift detection. During authoring, T04 corrected one task-plan API mismatch: the plan referenced `/api/build-lists/?user_id=...` but `buildListsApi.getBuildListsByUser` actually hits `/build-lists/user/{userId}` — captured as MEM117. Three baseline PNGs landed under `e2e/parts-catalog.spec.ts-snapshots/`. 5 passed + 4 intentionally skipped (mobile/tablet skips on dialog and Tab tests).

**T05 — Verification sweep.** Ran the full local gauntlet from `frontend/`: type-check 0, vitest 6/6 (PartsCatalog 3 + PartList.priceHistory 3, with documented pre-existing usePartPriceSummaries stderr from S06 mocks), lint 108 errors (zero in any S10-touched file — the +4 vs MEM062 baseline lives in PriceAlertSubscribeButton/AccountAlerts/ui/* outside slice scope), import-removal greps both exit 1 (no matches) confirming common/Input gone from PartsCatalog.tsx and ActionButton/SecondaryButton/common/Dialog gone from PartList.tsx + AddToBuildListDialog.tsx. Full e2e gauntlet (parts-catalog + price-history + components) initially failed 6 visual baselines in price-history.spec.ts — investigation showed all pre-screenshot assertions passed (sparkline, delta-line text, batch POST count, stale caveat); only fullPage pixel diffs failed with small height deltas (8-64px, ratios 0.01-0.07) caused by the ui/* primitives' slightly different padding/heights vs the legacy ActionButton/SecondaryButton/common/Input. Refreshed the 6 stale baselines via `--update-snapshots` (smaller blast radius than rolling back T01-T03; the S06 baselines captured the legacy design system, S10's intent IS to migrate). Re-ran the full gauntlet: 17 passed, 4 intentionally skipped, exit 0. Captured MEM113 / MEM115 (gotcha+pattern): future S12 ripple-reskin slices should expect baseline-refresh sweeps for any spec that screenshots a touched page — the baseline refresh is part of the reskin slice, not a follow-up.

**Patterns established / inherited and proven:** (1) MEM107 carve-out — page reskin = interactive primitives only, layout chrome stays for S12 sweep — applied successfully again across 5 files; (2) MEM111 — formal variants (destructive/secondary/link) over bespoke className color overrides — applied to all six row-action buttons + Cancel + the three clear-buttons; (3) Playwright multi-viewport spec template (cookie consent + chrome-extension dismiss + pinned Date.now + pageerror re-throw + default 404 mock-miss + scrollIntoViewIfNeeded for IO-gated content) reused unchanged from price-history.spec.ts; (4) S06 invariant (exactly 1 batch POST per displayed page) preserved and asserted by the new spec — the row-action variant migration in T02 did not regress the price-cell render path.

**What S11/S12/S13 should know:** /parts is now on the new design system for interactive primitives. SortableTh, ResponsiveTableWrapper, Pagination, PageHeader, VehicleFilterSection, VehicleFilterChips, Card, SectionHeader, ErrorAlert, LoadingSpinner — all still legacy, all bundled into S12's ripple sweep. The S10 baselines (parts-catalog visual regression at three viewports) are now the truth-source for how /parts should look post-S08 — S12's sweep can use these as regression evidence. AccountAlerts.tsx still has the open MEM102 self-cancelling-useEffect bug; lint baseline is now 108 errors (was 104 in MEM062) with the +4 in PriceAlertSubscribeButton/AccountAlerts/ui/* — folding those into a future slice is up for grabs.
